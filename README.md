# ViVakitchen Санкт-Петербург — сайт салона

Production-ready MVP сайта мебельного салона (официальный салон фабрики ViVakitchen
в Санкт-Петербурге). Next.js 15 (App Router) + TypeScript + Tailwind CSS.

## 1. Что реализовано

- Главная страница: hero, trust strip, категории, проекты, «Почему салон»,
  этапы заказа, блок для дизайнеров, производство/видео, форма расчёта,
  контакты/карта.
- Разделы: `/projects`, `/projects/[slug]`, `/kitchens`, `/wardrobes`,
  `/designers`, `/about`, `/contacts`, `/privacy`.
- Форма «Рассчитать проект» с загрузкой файла, валидацией обязательных
  полей, чекбоксом согласия на обработку персональных данных.
- CRM-абстракция (`services/crm.ts`) с mock-режимом — заявки не теряются,
  даже если Kaiten ещё не подключён (см. п. 13).
- UTM-трекинг (localStorage) и события аналитики для Яндекс Метрики.
- SEO: metadata API, sitemap.xml, robots.txt, JSON-LD `LocalBusiness`.
- Все бизнес-данные (телефон, email, адрес, соцсети, название бренда)
  централизованы в `config/site.ts` — ничего не зашито в компонентах.
- Категории и 8 проектов используют реальные фотографии фабрики
  ViVakitchen (взяты из официального каталога
  viva-kitchen.com/realizovannyye-proyekty) — см. п. 2а ниже про статус
  этих фото. Оставшиеся места без реальных материалов (салон, владелец,
  видео производства) — явные подписанные placeholder-блоки («Фото: …»),
  однозначно временные.

### 2а. Важно про источник фотографий проектов

Фото в `data/projects.ts` и `data/categories.ts` — это реальная съёмка
**фабрики** ViVakitchen из её официального каталога реализованных
проектов, а не фотографии, сделанные именно этим салоном в
Санкт-Петербурге. Это настоящие интерьеры на настоящей продукции
ViVakitchen, что и требовалось («не использовать случайные stock-фото»),
но сам салон не обязательно устанавливал именно эти конкретные объекты —
поэтому в описаниях используется формулировка «проект фабрики
ViVakitchen», а не «наш проект» или «мы сделали». **Перед запуском
желательно заменить эти фото на реализации именно петербургского
салона** (как только они появятся — через Telegram-канал фабрики или
собственные съёмки), но по художественному уровню и достоверности
происхождения текущий набор полностью пригоден для запуска.

## 2. Структура проекта

```
app/                    страницы (App Router)
  api/lead/              POST-обработчик формы → CRM
  api/upload/            загрузка приложенного файла
  projects/[slug]/       страница одного проекта
  sitemap.ts, robots.ts
components/
  sections/              крупные блоки страниц (Hero, Header, Footer, ...)
  ui/                     переиспользуемые примитивы (Button, Section, ...)
config/site.ts            все редактируемые бизнес-данные
data/                     контент-модель (projects.ts, categories.ts)
services/crm.ts           абстракция над Kaiten
lib/                      analytics.ts, utm.ts, clsx.ts
public/uploads/           локальное хранилище приложенных файлов (mock)
```

## 3. Запуск локально

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Форма расчёта работает «из коробки» —
без Kaiten и без Яндекс Метрики заявки просто логируются в консоль сервера
(`[crm mock] ...`).

## 4. Production build

```bash
npm run build
npm run start
```

Проект не привязан к Vercel: это обычное Next.js-приложение (`next start`),
его можно развернуть на Timeweb Cloud, Selectel, Reg.ru, любом Node-хостинге
или в Docker. Единственное, что требует «настоящего» Node-сервера (не
serverless/статик-экспорт) — загрузка файлов в `/api/upload` (см. п. 12).

## 5. Где что менять

| Что | Файл |
|---|---|
| Название бренда, телефон, email, адрес, соцсети | [`config/site.ts`](config/site.ts) |
| Тексты CTA-кнопок | ищите вызовы `<Button>` в `components/sections/*` и `app/**/page.tsx` — текст передаётся как children, единого «реестра CTA» нет, т.к. их немного |
| Добавить новый проект | добавить объект в [`data/projects.ts`](data/projects.ts) — страница `/projects/[slug]` и карточки на главной подхватят его автоматически |
| Категории на главной | [`data/categories.ts`](data/categories.ts) |
| Заменить фото проекта/категории | заменить файл в `public/images/projects/<slug>/` или `public/images/categories/`, путь в `data/projects.ts`/`data/categories.ts` менять не нужно, если имя файла то же |
| Заменить оставшийся placeholder (салон, владелец) | найти `<PlaceholderImage label="...">` в нужном компоненте/странице (сейчас — только `app/about/page.tsx`) и заменить на `<CoverImage src="/images/..." alt="..." />` (см. `components/ui/CoverImage.tsx`), положив файл в `public/images/...` |
| Видео о производстве | `components/sections/Production.tsx` → `<Video src="/video/production.mp4" poster="..." />` (сейчас видео не передано — показывается TODO-заглушка, ролик не грузится, пока не задан src) |
| Политика конфиденциальности | [`app/privacy/page.tsx`](app/privacy/page.tsx) — черновик, нужна проверка юристом |

## 6. Как подключить Яндекс Метрику

1. Создать счётчик в Яндекс Метрике.
2. Скопировать `.env.example` → `.env.local`, вписать
   `NEXT_PUBLIC_YANDEX_METRIKA_ID=XXXXXXXX`.
3. Готово — `components/YandexMetrika.tsx` подключит счётчик автоматически
   на всех страницах.

Уже прокинуты и вызываются все события из ТЗ (`lib/analytics.ts`):
`lead_form_open`, `lead_form_submit`, `phone_click`, `email_click`,
`map_click`, `project_open` (клик по карточке/ссылке проекта),
`designer_cta_click` (CTA «Обсудить проект» в блоке для дизайнеров и на
странице `/designers`), `video_play`.

## 7. Как подключить Kaiten

1. В Kaiten создать доску и колонку «Новый клиент», получить API-токен.
2. В `.env.local` заполнить:
   ```
   KAITEN_API_TOKEN=...
   KAITEN_API_URL=https://<ваш-домен>.kaiten.ru/api/latest
   KAITEN_BOARD_ID=...
   KAITEN_COLUMN_ID=...
   ```
3. `services/crm.ts` → `sendLeadToKaiten()` начнёт реально создавать карточки
   вместо логирования. UI формы менять не нужно — он вызывает
   `submitLead()`, которая ничего не знает про Kaiten.

Если в будущем Kaiten заменят на другую CRM — переписать нужно только
`services/crm.ts`.

## 8. Загрузка файлов (текущее ограничение)

`/api/upload` сохраняет файл на диск сервера в `public/uploads/` — это
работает на обычном Node-сервере (`next start`, Docker), но **не** будет
работать на serverless-платформе с read-only файловой системой. Если сайт
будет размещён на такой платформе — до запуска нужно заменить это на
S3-совместимое хранилище (Яндекс Object Storage, Selectel S3 и т.п.).

## 11. Известное и осознанно отложенное

`npm audit` показывает низко-критичные уязвимости в **встроенном**
(nested) `postcss`, который Next.js использует внутри себя для сборки
(`next/node_modules/postcss@8.4.31`) — не в зависимостях этого проекта
(наш собственный `postcss` уже на патченной версии 8.5.x). Исправляется
только мажорным апгрейдом на Next.js 16, который в рамках этого MVP
сознательно не делался — 16 вносит breaking changes, которые стоит
тестировать отдельно, не «попутно» с первым релизом.
